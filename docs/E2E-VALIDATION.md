# WordPress FSE Theme - End-to-End Validation Guide

Complete validation procedures for WordPress Full Site Editing (FSE) themes generated by the Figma-to-FSE pipeline.

---

## Overview

This guide covers 8 validation phases:

1. **Pre-Installation Validation** - Structure and syntax before WordPress
2. **WordPress Installation Testing** - Activation and error checking
3. **Visual Validation** - Design fidelity and rendering
4. **Functional Validation** - Links, navigation, interactivity
5. **Cross-Browser Testing** - Browser compatibility
6. **Performance Validation** - Lighthouse and Core Web Vitals
7. **Accessibility Validation** - WCAG 2.1 AA compliance
8. **Validation Checklist** - Complete sign-off template

---

## Prerequisites

Before starting validation:

- [ ] Docker Desktop running
- [ ] Theme exists in `themes/<theme-name>/`
- [ ] Node.js 22.12+ installed (for Playwright)
- [ ] Playwright installed (`npm install -g playwright && npx playwright install`)

## Phase 1: Pre-Installation Validation

Validate theme structure before installing in WordPress.

### 1.1 Run Unified Theme Validator

```bash
./scripts/validate-theme.sh <theme-name>
```

**Expected output:**
```
============================================
  Theme Validation: <theme-name>
============================================

--- 1. Required Files ---
  PASS: style.css exists
  PASS: theme.json exists
  PASS: templates/ directory exists
  PASS: parts/ directory exists
  PASS: templates/index.html exists

--- 2. Security Scan ---
  PASS: All PHP files pass security scan

...

============================================
  RESULTS: <theme-name>
============================================
  Passed:   12
  Warnings: 0
  Failed:   0

  Status: PASSED (all checks clean)
```

### 1.2 Required Files Checklist

Manually verify these files exist:

| File | Required | Purpose |
|------|----------|---------|
| `style.css` | Yes | Theme metadata and styles |
| `theme.json` | Yes | FSE configuration and design tokens |
| `templates/index.html` | Yes | Main fallback template |
| `templates/front-page.html` | Recommended | Homepage template |
| `templates/single.html` | Recommended | Single post template |
| `templates/page.html` | Recommended | Page template |
| `templates/404.html` | Recommended | Error page template |
| `parts/header.html` | Recommended | Header template part |
| `parts/footer.html` | Recommended | Footer template part |
| `functions.php` | Optional | PHP functions and hooks |
| `patterns/` | Optional | Block patterns directory |

**Verification command:**
```bash
ls -la themes/<theme-name>/
ls -la themes/<theme-name>/templates/
ls -la themes/<theme-name>/parts/
```

### 1.3 Validate theme.json

Check theme.json is valid JSON and contains required sections:

```bash
# Validate JSON syntax
cat themes/<theme-name>/theme.json | python -m json.tool > /dev/null && echo "PASS: Valid JSON" || echo "FAIL: Invalid JSON"

# Check for required sections
cat themes/<theme-name>/theme.json | python -c "
import json, sys
data = json.load(sys.stdin)
required = ['version', 'settings', 'styles']
missing = [r for r in required if r not in data]
if missing:
    print(f'FAIL: Missing sections: {missing}')
    sys.exit(1)
print('PASS: All required sections present')
print(f'  - version: {data.get(\"version\")}')
print(f'  - settings.color.palette: {len(data.get(\"settings\", {}).get(\"color\", {}).get(\"palette\", []))} colors')
print(f'  - settings.typography.fontFamilies: {len(data.get(\"settings\", {}).get(\"typography\", {}).get(\"fontFamilies\", []))} fonts')
"
```

**Expected output:**
```
PASS: Valid JSON
PASS: All required sections present
  - version: 2
  - settings.color.palette: 8 colors
  - settings.typography.fontFamilies: 3 fonts
```

### 1.4 Check for Common Issues

```bash
# Check for hardcoded colors (should use tokens)
grep -r "#[0-9A-Fa-f]\{6\}" themes/<theme-name>/templates/ themes/<theme-name>/parts/ 2>/dev/null && echo "WARN: Found hardcoded colors" || echo "PASS: No hardcoded colors in templates"

# Check for inline images in templates (should be in patterns)
grep -r "<img" themes/<theme-name>/templates/ 2>/dev/null && echo "WARN: Found <img> tags in templates (move to PHP patterns)" || echo "PASS: No inline images in templates"

# Check for empty src attributes
grep -r 'src=""' themes/<theme-name>/ 2>/dev/null && echo "FAIL: Found empty src attributes" || echo "PASS: No empty src attributes"
```

## Phase 2: WordPress Installation Testing

Install and activate theme in local WordPress.

### 2.1 Start WordPress Environment

```bash
# Start Docker containers
./wordpress-local.sh start

# Wait for WordPress to be ready (first time takes 1-2 minutes)
./wordpress-local.sh status
```

**Expected output:**
```
===================================
WordPress Status
===================================
NAME              COMMAND                  STATUS          PORTS
flavian-db        "docker-entrypoint.s..." Up 2 minutes    3306/tcp
flavian-wp        "docker-entrypoint.s..." Up 2 minutes    0.0.0.0:8080->80/tcp
flavian-phpmyadmin "/docker-entrypoint...." Up 2 minutes    0.0.0.0:8081->80/tcp
```

### 2.2 Install WordPress (First Time Only)

```bash
./wordpress-local.sh install
```

**Expected output:**
```
===================================
Installing WordPress
===================================
Success: WordPress installed successfully.

Admin Login:
  - URL:      http://localhost:8080/wp-admin
  - Username: admin
  - Password: admin
```

### 2.3 Activate Theme

```bash
./wordpress-local.sh activate-theme <theme-name>
```

**Expected output:**
```
===================================
Activating Theme: <theme-name>
===================================
Success: Switched to '<Theme Name>' theme.
Theme '<theme-name>' activated!
View at: http://localhost:8080
```

### 2.4 Enable Debug Mode

Enable WordPress debugging to catch PHP errors:

```bash
# Enter WordPress container
docker compose exec wordpress bash

# Add debug constants to wp-config.php (inside container)
wp config set WP_DEBUG true --raw --allow-root
wp config set WP_DEBUG_LOG true --raw --allow-root
wp config set WP_DEBUG_DISPLAY false --raw --allow-root
exit
```

### 2.5 Check for PHP Errors

```bash
# View debug log
docker compose exec wordpress cat /var/www/html/wp-content/debug.log 2>/dev/null || echo "No debug.log (good - no errors)"

# Check for fatal errors
docker compose exec wordpress grep -i "fatal\|error\|warning" /var/www/html/wp-content/debug.log 2>/dev/null | head -20 || echo "PASS: No PHP errors found"
```

**Expected output:**
```
No debug.log (good - no errors)
```
or
```
PASS: No PHP errors found
```

### 2.6 Verify Theme in Admin

1. Open http://localhost:8080/wp-admin
2. Navigate to Appearance > Themes
3. Verify theme shows correct:
   - Screenshot (if provided)
   - Theme name
   - Version
   - Author

### 3.4 Color Token Verification

```bash

import json, sys

palette = data.get('settings', {}).get('color', {}).get('palette', [])
print('Defined colors:')
for color in palette:
    print(f'  --wp--preset--color--{color[\"slug\"]}: {color[\"color\"]}')
"
```

1. Open DevTools (F12) in browser
2. Inspect any element
3. Check Computed Styles for color values
4. Verify CSS custom properties match theme.json

## Phase 6: Performance Validation

### 6.1 Lighthouse Audit

Run Lighthouse in Chrome DevTools or CLI:

```bash
# Install Lighthouse CLI
npm install -g lighthouse

# Run Lighthouse audit
lighthouse http://localhost:8080 --output=html --output-path=./.claude/reports/lighthouse-report.html --chrome-flags="--headless"
```

**Or use Chrome DevTools:**
1. Open http://localhost:8080 in Chrome
2. Press F12 to open DevTools
3. Go to Lighthouse tab
4. Select all categories
5. Click "Analyze page load"

### 6.2 Target Scores

### 6.3 Core Web Vitals

| Metric | Target | Actual | Status |
|--------|--------|--------|--------|
| LCP (Largest Contentful Paint) | < 2.5s | ___ | [ ] Pass |
| FID (First Input Delay) | < 100ms | ___ | [ ] Pass |

### 6.4 Image Optimization Check

```bash
# Check for unoptimized images (over 500KB)
find themes/<theme-name>/assets -type f \( -name "*.jpg" -o -name "*.png" -o -name "*.webp" \) -size +500k 2>/dev/null && echo "WARN: Large images found" || echo "PASS: All images under 500KB"

# Check if WebP versions exist
find themes/<theme-name>/assets -name "*.webp" 2>/dev/null | wc -l
```

### 6.5 Performance Recommendations

Common issues and fixes:

| Issue | Solution |
|-------|----------|
| Large images | Compress with `./scripts/wordpress/optimize-images.sh` |
| Render-blocking CSS | Load non-critical CSS async |
| No caching | Add caching plugin (production) |
| Large bundle | Code split if using build tools |

## Troubleshooting

### Common Issues

| Issue | Solution |
|-------|----------|
| Theme won't activate | Check style.css header format |
| White screen of death | Check debug.log for PHP errors |
| Styles not loading | Verify theme.json is valid JSON |
| Images broken | Move images to PHP patterns |
| Fonts not loading | Check font file paths in theme.json |
| Colors wrong | Verify design token slugs match usage |

### Getting Help

- **Debug log location:** `/var/www/html/wp-content/debug.log` (in container)
- **View logs:** `docker compose exec wordpress cat /var/www/html/wp-content/debug.log`
- **Troubleshooting guide:** See `docs/TROUBLESHOOTING.md`
- **Common failures:** See `docs/COMMON-FAILURES-FIXES.md`
